# 混沌演练方法论

> 本仓库的 70+ 项演练不是随机"搞破坏"，而是一套可复现的韧性验证方法。
> 本文档说明：故障注入分类、演练设计原则、已知边界。

## 一、故障注入分类学

| 类别 | 代号 | 模拟的故障 | 演练脚本 |
|---|---|---|---|
| 进程崩溃 | D1 | 主星被杀/崩溃，心跳消失 | `drill-supervisor` A、`drill-loop`、`drill-p2b` B/C |
| 功能性故障 | D2 | 进程活但配置被改坏（L3 自检 degraded） | `drill-p2` B |
| 挂死 | D3 | 进程活但心跳停（写路径被堵） | `drill-chaos` S1 |
| 启动即崩 | BOOT_GRACE | 新版本/坏配置导致 boot loop | `drill-chaos` S2、`drill-p2b` C |
| 配置损坏 | — | cordis.patch.yml 语法/结构损坏 | `drill-p2` C、`drill-p2b` C |
| 崩溃残留 | — | 改到一半崩溃，留下 open 账目 | `drill-supervisor` B |
| 升级重启 | — | 需重启生效的修改（受控自重启验证） | `drill-p2b` B/C |
| 阶梯用尽 | — | 无账目/快照可救 → 顶班 | `drill-p3`、`drill-chaos` S2/S3 |
| 顶班被杀 | — | 代班实例意外退出 → 自愈重启 | `drill-chaos` S3 |
| 组合故障 | — | 杀主星 + 坏 patch 同时注入 | `drill-chaos` S4 |
| 长时随机 | — | 多轮随机故障 + 恢复时间统计 | `soak.js` |
| 受控关闭 | — | control/shutdown 优雅停止 | `drill-shutdown` A |
| 孤儿检测 | — | 父进程死亡 → 监督者自清理 | `drill-shutdown` B |
| 所有权交接 | — | 桌面壳主星 → 监督者接管 | `drill-handover` |

## 二、演练设计原则（本仓库每个 drill 都遵守）

1. **干净起跑**：重置 state/心跳/锁/账本后再注入，防止上一轮遗留数据"骗过"检查
   （`state.primary.since` 必须晚于本轮启动，而不是遗留的 RUNNING）。
2. **故障必须真实有效**：注入后先自证——如坏 patch 必须让 `--dump-config` 非零退出，
   才继续等待自愈；否则"恢复"可能是假阳性。
3. **恢复判定绑定事件**："健康"由监督者确认（state.since 晚于故障时刻 + 心跳 ok +
   pid 已更换），不是看进程活着。
4. **安全边界显式声明**：每个 drill 顶部注明只碰 `profiles/sbx` 与独立状态目录
   `binary-star-sbx`；涉及 storages 的演练前后备份还原。
5. **清理即断言**：演练结束必须杀净进程树、还原 patch、验证无残留，否则判定失败。

## 三、已知边界（测试无法覆盖的部分）

- **组合/长时故障**：`drill-chaos` S4 与 `soak.js` 是增量覆盖，但真实环境的组合
  故障空间是无限的——建议按自己的工作负载扩展 soak 故障池。
- **外部依赖故障**：外部 API 不可用、网络分区、第三方服务宕机**不属于本系统修复范围**。
  单机文件通信设计保证外部网络故障不影响监督者判断；但"修复"只能作用于本机
  profiles/配置/进程。
- **硬件故障**：磁盘物理损坏、断电等超出软件自愈能力，靠快照 + 备份策略兜底。
- **探针盲区**：功能探针覆盖 进程/HTTP/心跳 health/状态目录可写；会话层深度冒烟
  仍是占位（`probe.js` 的 `sessionSmoke`）。

## 四、如何扩展演练

```js
// 新故障类型的最小模板（参考 scripts/drill-*.js）
// 1. 顶部声明安全边界与推导路径（不含硬编码绝对路径）
// 2. 干净起跑（重置 state/心跳/锁）
// 3. 注入故障并自证（如 dump-config 必须失败）
// 4. 等待自愈（轮询 state + 心跳 + pid 变化）
// 5. 断言 + 清理 + 无残留验证
// 6. 结果统计 PASS/FAIL，非零退出码
```

新增故障类别后，同步更新本表与 `docs/drills.md`。
